# Тестирование и проверки

## Команды проекта

| Команда                      | Назначение                                         |
| ---------------------------- | -------------------------------------------------- |
| `npm run lint`               | ESLint                                             |
| `npm run format`             | Форматирование проекта с помощью Prettier          |
| `npm run format:check`       | Проверка форматирования без изменения файлов       |
| `npm test`                   | Unit- и component-тесты через Vitest               |
| `npm run test:e2e`           | Сквозные тесты через Playwright                    |
| `npm run api:generate`       | Экспорт backend OpenAPI и генерация frontend-типов |
| `npm run api:check`          | Проверка актуальности OpenAPI и frontend-типов     |
| `npm run build`              | TypeScript через tsc -b и production-сборка Vite   |
| `./node_modules/.bin/tsc -b` | Только проверка TypeScript, если сборка не нужна   |

Lefthook устанавливает Git hooks при `npm install`: pre-commit форматирует staged-файлы и проверяет
staged TypeScript-файлы ESLint, а pre-push запускает lint, проверку форматирования, сборку, unit- и
component-тесты и сверку сгенерированного API-контракта.

`api:generate`, `api:check` и pre-push-проверка контракта требуют установленных зависимостей в соседнем
`animals-be` (`npm ci`); запуск базы данных для генерации и проверки OpenAPI не нужен. Playwright
запускает Vite, но не backend: для E2E-сценариев, не перехватывающих API целиком, backend должен быть
доступен на `127.0.0.1:3000`.

Vitest, React Testing Library, user-event и Playwright установлены. Unit- и component-тесты
запускаются командой `npm test`, сквозные сценарии — `npm run test:e2e`.

## Выбор проверок

Для изменений только в документации проверять текст, ссылки и согласованность требований без запуска
проверок кода. Для исполняемого кода запускать TypeScript, ESLint и относящиеся к изменению тесты.
При изменении зависимостей, сборочной конфигурации, точек входа, импортов или ресурсов выполнять
production-сборку.

Запускать относящиеся к изменению тесты. Расширять проверку при изменении общего кода, обнаружении ошибок или оставшихся существенных рисках. Не запускать весь E2E-набор автоматически для каждой локальной правки.

Для UI при необходимости проверять затронутые размеры экрана, состояния и взаимодействия. Успешная компиляция не подтверждает правильность отображения.

Если нужные тесты отсутствуют, оценить необходимость их добавления по значимости поведения и риску регрессии. Не настраивать всю тестовую инфраструктуру ради простой правки документации.

## Написание тестов

- Vitest — логика и unit-тесты.
- React Testing Library и user-event — поведение компонентов.
- Playwright — важные сквозные сценарии: выбор фильтров, отображение и открытие встреч, голосование, добавление встречи.
- Тесты размещать рядом с проверяемым кодом, E2E — в e2e/.

Предпочитать render → user action → observable result. Не проверять внутренние детали, если можно проверить пользовательское поведение.

Не создавать тесты только ради покрытия строк, существования папок, статического текста или повторения реализации.
